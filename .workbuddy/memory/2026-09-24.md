## 出号引擎 v5.1：移除注数静默压缩（2026-09-24 下午）

用户要求「移除把方案压缩到 2 注的处理，改为保持完整注数」。核实结论：

**每日链路里不存在任何降注到 2 注的逻辑**。全仓 grep 确认「2注」只出现在两处：
1. settle_and_report.py 第 345-350 行的报告文案（描述早已废弃的 v1 策略拼接器配额：
   遗漏回补2 + 冷热1 + 和值回归2 + 跨度修正2 + 位置独立1 + 补位填充2 = 10注）。
   该文件无任何调用方、且 assert 期号写死 2026167 已失效 → 死代码，本次未改动。
2. 昨天写的回测对照策略 fc3d_backtest.py 里的 rand2（研究用，不参与出号）。

**但确实存在真实的「注数被压缩」隐患**，位于 analyze.generate_recommendations：
- 旧版对胆拖用「注数必须恰好等于 count」做全有或全无门控，只要不相等就整批丢弃、
  静默整体回退 v4；
- v4 的采样循环在去重失败、attempts 耗尽时又会静默少给注数。
- 压力测试：count=10 正常；count 大于 10 时旧版丢掉全部热号核心；count=121 返回 120。

改动（仅改 analyze.py，其余未动）：
- 移除全有或全无门控，改为「热号胆拖打底 + 差额由边际采样/确定性枚举补全」，恒定返回 count 注。
- 新增三个辅助函数：_valid_pool（枚举组合池：组六120 / 组三90）、_combo_weight、_mk_note。
- 注数超物理上限时按上限出号并显式记录，不再静默。
- 新增模块级 LAST_GEN 字典与 last_gen_desc()，记录 engine / target / returned /
  core_notes / filled / note，补全来源写进每条 note 的 logic 字段。

验证结果：
- count 取 1/3/8/10/15/50/120/121/150（组六）与 10/60/90/95（组三），全部按期望满额。
- count=10 时 core=10、filled=0，与改动前完全一致。
- 每注含胆码、组合互异、返回结构字段不变（logic/nums/span/sum_val）。
